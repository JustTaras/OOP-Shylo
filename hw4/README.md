“Factory vs Abstract Factory: вибір”
Вступ
Породжувальні патерни (creational patterns) призначені для гнучкого створення об’єктів без жорсткої прив’язки до конкретних класів. Серед них важливе місце займають Factory Method та Abstract Factory. Обидва патерни інкапсулюють процес створення об’єктів, але застосовуються в різних ситуаціях і мають різний рівень складності.

1. Factory Method
Суть патерну
Factory Method (Фабричний метод) — це патерн, який визначає інтерфейс для створення об’єкта, але дозволяє підкласам вирішувати, який саме клас буде створений.
Тобто базовий клас оголошує метод створення об’єкта (factory method), а конкретні підкласи реалізують його по-своєму.
Коли використовувати


Коли клас не знає заздалегідь, об’єкти яких саме підкласів потрібно створювати.


Коли потрібно делегувати створення об’єктів підкласам.


Коли є одна ієрархія продуктів.


Приклад сценарію
Наприклад, програма створює документи:


PdfDocument


WordDocument


Є базовий клас DocumentCreator, який має метод CreateDocument().
Підкласи (PdfCreator, WordCreator) перевизначають цей метод і створюють відповідний тип документа.
Переваги


Зменшує залежність від конкретних класів.


Дотримується принципу відкритості/закритості (OCP).


Простий у реалізації.


Недоліки


Збільшується кількість підкласів.


Підходить лише тоді, коли створюється один тип продукту.



2. Abstract Factory
Суть патерну
Abstract Factory (Абстрактна фабрика) — це патерн, який надає інтерфейс для створення сімейства пов’язаних або взаємозалежних об’єктів без зазначення їх конкретних класів.
Тобто фабрика створює не один об’єкт, а групу взаємопов’язаних об’єктів.
Коли використовувати


Коли система повинна бути незалежною від способу створення об’єктів.


Коли потрібно створювати сімейства пов’язаних об’єктів.


Коли важливо забезпечити узгодженість між продуктами.


Приклад сценарію
Приклад — кросплатформний графічний інтерфейс.
Є два сімейства елементів:


Windows: WindowsButton, WindowsCheckbox


MacOS: MacButton, MacCheckbox


Інтерфейс GUIFactory має методи:


CreateButton()


CreateCheckbox()


Конкретні фабрики (WindowsFactory, MacFactory) створюють узгоджені компоненти однієї платформи.
Переваги


Гарантує сумісність створених об’єктів.


Легко замінити ціле сімейство продуктів.


Відповідає принципу інверсії залежностей (DIP).


Недоліки


Складніша структура.


Важко додати новий тип продукту (потрібно змінювати всі фабрики).


Більше коду та інтерфейсів.

Коротко:


Factory Method — коли потрібно створювати один тип продукту, але його конкретний клас може змінюватися.


Abstract Factory — коли потрібно створювати кілька пов’язаних об’єктів, які мають працювати разом.



Висновок
Обидва патерни допомагають зменшити залежність коду від конкретних класів і підвищують гнучкість системи.
Якщо задача проста і потрібно лише делегувати створення одного об’єкта — достатньо Factory Method.
Якщо ж система працює з кількома взаємопов’язаними об’єктами і важлива їх узгодженість — краще використовувати Abstract Factory.
