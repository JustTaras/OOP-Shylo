Звіт до лабораторної роботи №20

Тема: Застосування принципу єдиної відповідальності (SRP)
Мета: Навчитися застосовувати принцип SRP шляхом декомпозиції класу OrderProcessor на окремі компоненти з чітко визначеними обов’язками.

Хід роботи

Було створено консольний проєкт lab20 мовою C#.

Реалізовано початковий клас OrderProcessor, який порушує принцип єдиної відповідальності, оскільки поєднує в собі логіку валідації замовлення, збереження даних, відправки email-повідомлень та оновлення статусу.

Виконано рефакторинг відповідно до принципу SRP:

функціональність розділено на окремі інтерфейси (IOrderValidator, IOrderRepository, IEmailService);

створено їх прості реалізації;

реалізовано клас OrderService, який координує роботу компонентів та використовує механізм Dependency Injection.

У методі Main продемонстровано роботу програми на прикладі валідного та невалідного замовлення.

Після рефакторингу код став більш структурованим, зрозумілим та легшим для підтримки.

Висновок

У результаті виконання лабораторної роботи було застосовано принцип єдиної відповідальності (SRP).
Рефакторинг дозволив розділити обов’язки між класами, що підвищило читабельність коду, спростило його тестування та покращило відповідність принципам SOLID.
